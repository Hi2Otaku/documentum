## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing, gap between form fields in dense layouts |
| md | 16px | Default element spacing, card padding, form field vertical gap |
| lg | 24px | Section padding (card content areas, panel padding — matches existing `p-6`) |
| xl | 32px | Layout gaps between major sections |
| 2xl | 48px | Page-level vertical spacing (type admin page top/bottom margins) |
| 3xl | 64px | Not used in this phase |

Exceptions: Table rows use 48px min-height (matching existing `min-h-[48px]` on DocumentTable rows). Filter bar height is 48px (matching existing `h-12`).

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 (regular) | 1.5 |
| Label | 12px (`text-xs`) | 400 (regular) | 1.5 |
| Heading | 16px (`text-base`) | 600 (`font-semibold`) | 1.2 |
| Display | 20px (`text-lg`) | 600 (`font-semibold`) | 1.2 |

Source: Extracted from existing codebase patterns. DocumentDetailPanel uses `text-base font-semibold` for section headings, `text-sm` for body content, `text-xs text-muted-foreground` for labels. No fourth size (display) is used in existing pages but is declared for the admin page title if needed.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `oklch(1 0 0)` / `--color-background` | Page background, panel surfaces |
| Secondary (30%) | `oklch(0.965 0 0)` / `--color-secondary` | Table headers (`bg-secondary`), filter bars (`bg-secondary/50`), cards, sidebar |
| Accent (10%) | `oklch(0.965 0 0)` / `--color-accent` | Selected table row highlight (`bg-accent/50`), active sidebar item |
| Destructive | `oklch(0.577 0.245 27.325)` / `--color-destructive` | Delete Type button, type change warning icon |

Accent reserved for: selected row in type list table, active nav item highlight, focused input ring (`--color-ring`). Not for general buttons — primary buttons use `--color-primary` (dark neutral).

Note: The existing color system is achromatic neutral (all oklch hue = 0). Accent and secondary are visually identical. Interactive distinction comes from opacity variants (`accent/50`) and border treatments (`border-l-[3px] border-primary` on selected rows). This phase follows the same pattern.

### TypeSelector (in document forms)

- Standard Select component, same styling as existing state filter selects
- Width: full-width within form column
- First option: "No type" (maps to null `document_type_id`)
- Options sorted alphabetically; child types indented with 2-space prefix in label: "  Invoice" under "Financial"
- On change: triggers re-render of TypeMetadataForm below

### TypeMetadataForm (dynamic fields)

```
+--------------------------------------------+
| Type-Specific Metadata                     |
+--------------------------------------------+
| Invoice Number *                           |
| [________________________]                 |
|                                            |
| Amount                                     |
| [________________________]                 |
|                                            |
| Payment Status                             |
| [Select...                v]               |
|                                            |
| Approved                                   |
| [ ] (checkbox)                             |
+--------------------------------------------+
```

- Section header: `text-sm font-semibold text-muted-foreground uppercase tracking-wider` (matches sidebar section headers)
- Field gap: 16px vertical (`space-y-4`)
- Field rendering by JSON Schema type:
  - `"type": "string"` — Input component
  - `"type": "number"` — Input with `type="number"`
  - `"type": "boolean"` — Checkbox component
  - `"type": "string", "format": "date"` — Input with `type="date"`
  - `"type": "string", "enum": [...]` — Select component with enum values as options
- Required fields: asterisk (*) appended to label, `text-destructive` color for asterisk
- Field order: follows `properties` key order from JSON Schema
- Inherited fields (from parent type): rendered first, with a subtle `text-xs text-muted-foreground` label "(inherited)" after the field label
- Validation errors: inline `text-sm text-destructive` below each field, populated from API 422 response

## Interaction Contracts

### Type CRUD Flow

1. **Create**: Click "Create Type" button on admin page -> Dialog opens -> Fill form -> Click "Save Type" -> Dialog closes -> Table refreshes -> Toast: "Type created"
2. **Edit**: Click "Edit" on table row -> Dialog opens pre-populated -> Modify -> Click "Save Type" -> Dialog closes -> Table refreshes -> Toast: "Type updated"
3. **Delete**: Click "Delete Type" in edit dialog footer -> Confirmation dialog: "Delete {name}? This will remove the type definition. Documents using this type will become untyped." -> Click "Delete" -> Both dialogs close -> Table refreshes -> Toast: "Type deleted"

### Type Selection on Document Upload

1. User drops/selects file in DocumentDropZone
2. After file selection, a pre-upload form appears (or TypeSelector is added to the existing upload flow)
3. User optionally selects a type from TypeSelector dropdown
4. If type selected: TypeMetadataForm renders below with type-specific fields
5. User fills required metadata fields
6. Upload proceeds; API validates metadata against schema
7. On validation error (422): toast with field-level errors, form fields show inline errors

### Type Change on Existing Document

1. User opens document detail panel
2. User changes type via TypeSelector
3. If existing metadata does not match new schema: warning banner appears: "Some existing metadata fields may not match the new type schema. Unmatched fields will be preserved but not validated."
4. TypeMetadataForm re-renders with new type fields, pre-populated where field names match
5. User saves; API validates against new schema

### Loading States

- Type table: 5 skeleton rows (matching DocumentTable pattern)
- TypeSelector: disabled with "Loading types..." placeholder while fetching
- TypeMetadataForm: skeleton lines matching field count from schema (or 3 skeleton lines as default)
- Create/Edit dialog submit: button shows loading spinner, disabled during save

### Error States

- API fetch failure on type list: Toast error + empty state with retry button
- Schema JSON parse error: red border on textarea + inline error message below: "Invalid JSON: {parse error message}"
- Schema validation error on save: inline `text-destructive` below textarea: "Schema must define at least one property"
- Document save with type validation failure: field-level errors below each invalid field + toast summary: "Metadata validation failed: {count} field(s) have errors"

## Accessibility Notes

- All form fields must have associated Label components (not just visual labels)
- Dialog must trap focus and close on Escape (provided by Radix Dialog)
- TypeSelector must be keyboard navigable (provided by Radix Select)
- Schema editor textarea must have `aria-describedby` pointing to error message element when invalid
- Delete confirmation dialog must auto-focus the Cancel button (not Delete) for safety
- Required field indicators (*) must also have `aria-required="true"` on the input
