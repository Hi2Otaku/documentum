1. Create `src/app/tasks/audit_chain.py` with a Celery task `compute_audit_chain_hash`:
   - Task name: "app.tasks.audit_chain.compute_audit_chain_hash"
   - Accepts `audit_record_id: str` parameter
   - Uses `create_task_session_factory` pattern (same as notification.py) to get async DB session
   - Logic:
     a. Load the AuditLog record by id
     b. Compute `content_hash` = SHA-256 hex of a canonical JSON string of: `{"id": str(id), "timestamp": isoformat, "entity_type": ..., "entity_id": ..., "action": ..., "user_id": ..., "before_state": ..., "after_state": ..., "details": ...}` — use `json.dumps(data, sort_keys=True, default=str)` for determinism
     c. Find the previous record by chain_sequence (SELECT ... WHERE chain_sequence IS NOT NULL ORDER BY chain_sequence DESC LIMIT 1) or if no previous record exists, use "GENESIS" as the previous chain_hash
     d. Assign `chain_sequence` = (max existing chain_sequence + 1) or 1 if none exist. Use SELECT ... FOR UPDATE on the max chain_sequence row to prevent race conditions.
     e. Compute `chain_hash` = SHA-256 hex of `f"{content_hash}:{previous_chain_hash}"`
     f. Update the record with content_hash, chain_hash, chain_sequence
     g. Commit
   - Use `hashlib.sha256` from stdlib (no need for cryptography library for simple hashing)
   - Add bind=True, max_retries=3, default_retry_delay=5 for resilience
