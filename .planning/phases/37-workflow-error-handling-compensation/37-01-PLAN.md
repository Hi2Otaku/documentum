    1. In `src/app/services/engine_service.py`, add a completion order counter to `_advance_from_activity`:
       - When an activity transitions to COMPLETE, assign `completed_order` using an incrementing counter.
       - Query max(completed_order) for the workflow and set next = max + 1 (or 1 if none).

    2. Add `async def handle_activity_error(db, workflow, activity_instance, template, template_to_instance, user_id, error_msg, error_details_dict)` function:
       - Set activity_instance.state = ActivityState.ERROR
       - Set activity_instance.error_message = error_msg
       - Set activity_instance.error_details = error_details_dict
       - Look up the ActivityTemplate for this instance via activity_template_map
       - If template has error_handler_activity_id:
         - Find the corresponding ActivityInstance in template_to_instance
         - Activate the error handler activity (set ACTIVE, create work items if manual, or leave for agent if auto)
         - Log: "Error handler activated for activity {name}"
         - Return True (error was handled)
       - If no error handler: return False (unhandled, engine should halt or fail the workflow)

    3. Add `async def execute_compensation(db, workflow_id, user_id)` function:
       - Load workflow instance and all activity instances
       - Load the process template with activity_templates
       - Find all COMPLETE activity instances that have a compensation_activity_id on their template
       - Sort by completed_order DESC (reverse chronological)
       - For each, in order:
         - Find the compensation activity template
         - Create a new ActivityInstance for the compensation activity (or reuse if already exists)
         - If compensation activity is MANUAL: create work items for performers
         - If compensation activity is AUTO: set to ACTIVE for the Workflow Agent to pick up
         - Await completion (for auto) or mark as ready (for manual, which blocks further compensation until complete)
       - Set workflow state to HALTED after compensation starts (operator must resume or terminate)
       - Create audit record: "compensation_started"

    4. Add a new endpoint-callable function `async def trigger_compensation(db, workflow_id, user_id)`:
       - Validates workflow is in RUNNING or FAILED state
       - Calls execute_compensation
       - Returns the workflow instance

    5. In `src/app/tasks/auto_activity.py`, modify the error handling path:
       - After setting activity to ERROR state (at max retries exceeded), also set error_message and error_details on the ActivityInstance
       - After commit, check if the activity template has an error_handler_activity_id
       - If so, in a new session, call handle_activity_error to activate the handler
       - This integrates the existing retry-3-times-then-error pattern with the new error handler system

    6. Add state transition for compensation: add `(ActivityState.COMPLETE, ActivityState.DORMANT)` to ACTIVITY_TRANSITIONS to allow resetting completed activities during compensation if needed. Also add `(WorkflowState.RUNNING, WorkflowState.HALTED)` is already there -- verify.
