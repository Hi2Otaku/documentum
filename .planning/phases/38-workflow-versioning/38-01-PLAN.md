2. **template_service.py - create_new_version**: Set `template_family_id = original.template_family_id` on the new template (inherits the family from the source). Currently it copies name, description, version+1 -- add template_family_id to the copy.

3. **template_service.py - install_template**: Change the deprecation logic. Currently it deprecates ALL other installed templates with same name. New logic:
   - Query templates with same `template_family_id`, `is_installed == True`, `id != template.id`
   - For each old installed version: check if any WorkflowInstance references it with state in (RUNNING, HALTED, DORMANT)
     - If YES: leave it installed (is_installed=True) but set state to DEPRECATED. Running instances can still reference it.
     - If NO running instances: set is_installed=False and state=DEPRECATED (fully superseded)
   - This ensures WFVER-01: new version installs while old version's instances keep running.

4. **template_service.py - add list_template_versions**: New function:
   ```python
   async def list_template_versions(db: AsyncSession, template_family_id: UUID) -> list[ProcessTemplate]:
       """List all versions of a template family, ordered by version desc."""
       result = await db.execute(
           select(ProcessTemplate)
           .where(ProcessTemplate.template_family_id == template_family_id,
                  ProcessTemplate.is_deleted == False)
           .order_by(ProcessTemplate.version.desc())
       )
       return list(result.scalars().all())
   ```

5. **engine_service.py - start_workflow**: After loading the template by template_id, add a resolution step. If the template is not installed, try to find the latest installed version in its family:
   - Query `ProcessTemplate` where `template_family_id == template.template_family_id`, `is_installed == True`, `is_deleted == False`, ordered by `version DESC`, limit 1
   - Use that resolved template for instance creation
   - If no installed version found, raise ValueError("No installed version available for this template")
   - This ensures WFVER-02: new instances always get the latest installed version.

6. **workflow_mgmt_service.py - list_workflows_filtered**: Update the query to also select `ProcessTemplate.version.label("template_version")`. In the dict-building loop, include `template_version`.

7. **schemas/workflow.py - WorkflowAdminListResponse**: Add `template_version: int | None = None` field. This surfaces version info for WFVER-03.

8. **routers/templates.py**: Add a new endpoint:
   ```
   GET /templates/{template_id}/versions
   ```
   Returns list of ProcessTemplateResponse for all versions in the family of the given template_id. Uses the new `list_template_versions` function. Look up the template first to get its template_family_id, then call list_template_versions.
