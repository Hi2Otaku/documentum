  <action>
    Create src/app/services/cmis_query_service.py implementing a simple CMIS-QL parser.

    The parser handles this subset of CMIS-QL:
    ```
    SELECT <select_list> FROM <type_id> [WHERE <conditions>] [ORDER BY <sort_spec>]
    ```

    Where:
    - select_list: "*" | comma-separated CMIS property names
    - type_id: "cmis:document" | "cmis:folder"
    - conditions: property_name op value [AND|OR property_name op value]*
    - op: "=" | "!=" | "<" | ">" | "<=" | ">=" | "LIKE" | "IN"
    - value: 'string_literal' | number | ('val1', 'val2', ...) for IN
    - sort_spec: property_name [ASC|DESC] [, property_name [ASC|DESC]]*

    Implementation approach — use regex-based tokenizer (NOT a full parser library):
    1. parse_cmis_query(query: str) -> ParsedQuery dataclass with fields: select_fields, from_type, where_clauses (list of WhereClause), order_by (list of OrderSpec)
    2. WhereClause dataclass: property (str), operator (str), value (str | list)
    3. OrderSpec dataclass: property (str), direction ("ASC" | "DESC")

    execute_cmis_query(db: AsyncSession, query: str, user_id: str, is_superuser: bool, max_items: int = 100, skip_count: int = 0) -> dict:
    1. Call parse_cmis_query to get parsed structure
    2. Build SQLAlchemy select based on from_type (Document or Folder)
    3. Map where_clauses: use PROPERTY_MAP from cmis_service to translate cmis:name -> title, etc.
       - "=" -> column == value
       - "LIKE" -> column.ilike(value.replace("*", "%")) (CMIS uses % for wildcards, same as SQL)
       - "IN" -> column.in_(values)
       - AND/OR between clauses (default AND)
    4. Map order_by: translate property names, apply .asc() or .desc()
    5. Apply skip_count and max_items (LIMIT/OFFSET)
    6. Execute query, map results through to_cmis_document or to_cmis_folder
    7. If select_fields is not "*", filter succinctProperties to only requested fields
    8. Return {"objects": [...], "hasMoreItems": bool, "numItems": total_count}

    Error handling: if parse fails, raise ValueError with descriptive message. Router will catch and return CMIS invalidArgument error.

    Create src/tests/test_cmis_query.py with:
    - Unit tests for parse_cmis_query (parsing only, no DB)
    - Integration tests using db_session fixture: create test documents, then run execute_cmis_query and verify results
