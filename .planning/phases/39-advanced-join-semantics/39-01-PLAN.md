1. In src/app/services/engine_service.py, rewrite _should_activate():
   - Add SELECT ... FOR UPDATE on the ExecutionToken rows for this target (prevents concurrent duplicate activation). Use `with_for_update()` on the select query for token counting. This is the critical race condition fix (JOIN-04).
   - AND_JOIN: unchanged (token_count >= len(incoming_flows))
   - OR_JOIN: unchanged (token_count >= 1)
   - N_OF_M_JOIN: fire when token_count >= activity_template.join_threshold. The function signature must accept the ActivityTemplate object (not just trigger_type) so it can read join_threshold.
   - CANCELLING_JOIN: same firing logic as N_OF_M_JOIN (uses join_threshold, defaults to 1 if not set). After activation, cancel remaining branches (separate helper).
   - TIMEOUT_JOIN: same logic as AND_JOIN for normal firing. Timeout logic is handled by the Celery task.

2. Update _should_activate signature: add activity_template parameter (ActivityTemplate) to access join_threshold. Update all call sites in advance_workflow.

3. Add _cancel_remaining_branches() helper in engine_service.py:
   - Takes db, workflow_id, target_activity_template_id, flow_templates
   - Finds all ActivityInstance objects in the workflow that are DORMANT or ACTIVE and are on branches feeding into this join but have not yet produced a token
   - Sets their state to ActivityState.CANCELLED, sets completed_at = now
   - Also cancels any work items in non-terminal state for those activities

4. In the advance_workflow token-placement loop (around line 601), after `if should_fire:`:
   - If trigger_type is CANCELLING_JOIN, call _cancel_remaining_branches() after activation
   - If trigger_type is TIMEOUT_JOIN, set join_timeout_started_at on the target ActivityInstance when the first token arrives (if not already set)
