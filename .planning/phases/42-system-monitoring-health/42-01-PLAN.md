   - Fields: name (String(200), not null), metric_name (String(100), not null, e.g. "celery_queue_depth", "db_connection_ok", "redis_ping_ok", "minio_health_ok"), operator (String(10), not null — one of "gt", "lt", "eq", "gte", "lte"), threshold (Float, not null), enabled (Boolean, default=True), notification_message (Text, nullable)

4. Create `src/app/schemas/monitoring.py`:
   - ComponentHealth(BaseModel): name (str), status (Literal["healthy", "degraded", "unhealthy"]), latency_ms (float | None = None), details (str | None = None)
   - HealthResponse(BaseModel): status (Literal["healthy", "degraded", "unhealthy"]), components (list[ComponentHealth]), checked_at (datetime)
   - WorkerInfo(BaseModel): hostname (str), status (str), active_tasks (int), processed (int), pid (int | None = None)
   - QueueMetrics(BaseModel): queue_name (str), depth (int)
   - SystemMetrics(BaseModel): workers (list[WorkerInfo]), queues (list[QueueMetrics]), total_active_tasks (int), total_scheduled_tasks (int)
   - AlertRuleCreate(BaseModel): name (str), metric_name (str), operator (str), threshold (float), enabled (bool = True), notification_message (str | None = None)
   - AlertRuleUpdate(BaseModel): all fields optional
   - AlertRuleResponse(BaseModel): id (UUID), name, metric_name, operator, threshold, enabled, notification_message, created_at (datetime)

5. Create `src/app/services/monitoring_service.py`:
   - `async def check_database_health() -> ComponentHealth`: execute `SELECT 1` via engine, measure latency, catch exceptions -> unhealthy
   - `async def check_redis_health() -> ComponentHealth`: ping Redis via `redis.asyncio.from_url(settings.redis_url)`, measure latency
   - `async def check_celery_health() -> ComponentHealth`: use `celery_app.control.inspect().ping()` in a thread (it is sync), healthy if at least 1 worker responds
   - `async def check_minio_health() -> ComponentHealth`: call `minio_client.bucket_exists("documents")` in a thread, measure latency
   - `async def check_all_health() -> HealthResponse`: call all 4, aggregate: "healthy" if all healthy, "degraded" if any degraded, "unhealthy" if any unhealthy
   - `async def get_system_metrics() -> SystemMetrics`: use `celery_app.control.inspect()` methods (active, scheduled, stats) in a thread, parse into WorkerInfo list; use `celery_app.control.inspect().active_queues()` for queue info; for queue depth, use Redis LLEN on celery queue keys
   - `def generate_prometheus_metrics() -> str`: use `prometheus_client` — create a CollectorRegistry, add gauges: documentum_health_status (labels: component), documentum_celery_queue_depth (labels: queue), documentum_celery_workers_active, documentum_celery_tasks_active; generate latest text with `generate_latest(registry)`. Run synchronously since Prometheus scrapes are lightweight.
   - `async def evaluate_alert_rules(db: AsyncSession, health: HealthResponse, metrics: SystemMetrics) -> list[str]`: load enabled AlertRule rows, compare metric values against thresholds, return list of triggered rule names

  <action>
1. Create `src/app/routers/monitoring.py`:
   - router = APIRouter(prefix="/monitoring", tags=["monitoring"])
   - `GET /monitoring/health` -> calls `check_all_health()`, returns EnvelopeResponse[HealthResponse]. Require admin (current_user with is_superuser check).
   - `GET /monitoring/metrics` -> calls `get_system_metrics()`, returns EnvelopeResponse[SystemMetrics]. Require admin.
   - `GET /monitoring/alerts` -> list AlertRule rows from DB, returns EnvelopeResponse[list[AlertRuleResponse]]. Require admin.
   - `POST /monitoring/alerts` -> create AlertRule from AlertRuleCreate body, returns EnvelopeResponse[AlertRuleResponse]. Require admin.
   - `PUT /monitoring/alerts/{rule_id}` -> update AlertRule, returns EnvelopeResponse[AlertRuleResponse]. Require admin.
   - `DELETE /monitoring/alerts/{rule_id}` -> soft-delete AlertRule. Require admin.
   - For admin check, use the same pattern as other admin routers (Depends on get_current_user, check is_superuser, raise 403 if not).

2. Update `src/app/routers/health.py`:
   - Add a `GET /health/deep` endpoint that calls `check_all_health()` and returns the full component breakdown. This is unauthenticated (for load balancers / Docker healthchecks). Keep the existing simple `/health` endpoint unchanged.

3. Add a root-level `GET /metrics` Prometheus endpoint:
   - In `src/app/routers/monitoring.py` add a separate router (prometheus_router = APIRouter()) with a `GET /metrics` endpoint that calls `generate_prometheus_metrics()` and returns `Response(content=text, media_type="text/plain; version=0.0.4; charset=utf-8")`.
   - This endpoint is unauthenticated (Prometheus scrapers do not send auth tokens).

4. Create `src/app/tasks/health_check.py`:
   - Import celery_app from app.celery_app
   - `@celery_app.task(name="app.tasks.health_check.run_health_checks")`
   - `def run_health_checks()`: use `asyncio.run()` to call async check_all_health() + get_system_metrics(), then evaluate_alert_rules(); for each triggered alert, call create_notification for all superusers (query User where is_superuser=True). Use `create_task_session_factory()` for DB session. notification_type = "system_alert".

5. Update `src/app/celery_app.py`:
   - Add "app.tasks.health_check" to the `include` list
   - Add beat_schedule entry: "run-health-checks" with task "app.tasks.health_check.run_health_checks", schedule 60.0 (every 60 seconds)

6. Update `src/app/main.py`:
   - Import monitoring router: `from app.routers import monitoring`
   - Register: `application.include_router(monitoring.router, prefix=settings.api_v1_prefix)`
   - Register Prometheus router at root (no prefix): `application.include_router(monitoring.prometheus_router)`
